# trn2-bench — AWS Trainium2 (trn2.48xlarge) benchmark suite & report

A complete single-node evaluation of AWS Trainium2 (2026-11-07/08, us-east-2b, 29 h Capacity
Block), covering GEMM compute, HBM bandwidth, STREAM, H2D/D2H, collective communication, and
vLLM model inference (Qwen3-32B, DeepSeek-R1-Distill-Llama-70B), with every result verified
against AWS official specifications.

**Report**: [`report.md`](report.md) ｜ PDF: `Trainium2_trn2.48xlarge_benchmark_report.pdf`

## Results at a Glance

| item | measured | official | ratio |
|---|---|---|---|
| GEMM BF16 (full node, 16 chips) | 7.59 PFLOPs | 10.67 PF | 71% |
| GEMM BF16 (per chip) | 594 TF | 667 TF | 89% |
| HBM bandwidth (node, DMA) | 41.2 TB/s | 46 TB/s | 90% |
| NeuronLink (all-reduce busbw / chip) | ≈1.30 TB/s | 1.28 TB/s | ≈100% |
| Qwen3-32B TP32 decode throughput | 1099 tok/s (64 concurrent) | — | — |
| DS-R1-Distill-70B TP64 decode throughput | 774 tok/s (64 concurrent) | — | — |
| single-stream latency (both models) | 13.0 / 13.4 ms/token | — | — |

Environment: Neuron SDK 2.33 · torch-neuronx 2.14 (native `neuron` device) · vLLM-Neuron 0.29 ·
LNC=2 (64 logical cores × 24 GB)

## Layout

```
report.md                  # full report (incl. official-spec verification & pitfalls)
*.pdf                      # PDF version of the report
scripts/
  00_setup.sh              # NVMe RAID0 mount + system info collection
  common.py                # per-rank core pinning (NEURON_RT_VISIBLE_CORES)
  01_gemm.py               # GEMM TFLOPs (BF16/FP32, chained square matmuls)
  02_stream.py             # STREAM copy/scale/add/triad (framework elementwise path)
  03_h2d.py                # host<->device bandwidth
  04_collectives.sh        # nccom-test: all-reduce/all-gather/reduce-scatter/all-to-all
  05_hbm_copy.py           # on-device DMA copy_ (true HBM bandwidth)
  06_model_bench.sh        # vLLM throughput + latency
  07_decode_heavy.sh       # decode-heavy throughput rerun (512 output tokens)
  run_micro.sh / finish_suite.sh   # micro-benchmark orchestration
  aggregate.py             # aggregates results/ into markdown tables
results/                   # raw data: jsonl / nccom output / vLLM json (large logs truncated)
  summary_tables.md        # full data tables generated by aggregate.py
```

## Reproducing

```bash
# trn2.48xlarge + Neuron DLAMI (Ubuntu 24.04, SDK 2.33)
bash scripts/00_setup.sh
bash scripts/run_micro.sh && bash scripts/finish_suite.sh     # micro-benchmarks
bash scripts/06_model_bench.sh Qwen/Qwen3-32B qwen3-32b-tp32 32 4096
bash scripts/06_model_bench.sh deepseek-ai/DeepSeek-R1-Distill-Llama-70B ds-r1-70b-tp64 64 4096
bash scripts/07_decode_heavy.sh
python3 scripts/aggregate.py results > results/summary_tables.md
```

Key environment variables (see report §7 for the full pitfalls list): per-rank core pinning via
`NEURON_RT_VISIBLE_CORES`; on instances without EFA, vLLM needs `NEURON_SKIP_EFA_AFFINITY=1`.

## Running on Trn3

The same Neuron SDK stack supports Trn3, so the scripts run as-is with minor adjustments:
check `neuron-ls` for the chip count and logical-core (LNC) configuration on your instance size,
then adjust `--nproc_per_node` for the sweep levels (1 / cores-per-chip / all cores), the
`RANKS` list in `04_collectives.sh`, and the vLLM tensor-parallel size accordingly.
